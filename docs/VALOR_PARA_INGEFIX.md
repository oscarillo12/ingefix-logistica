# Valor operativo para INGEFIX

El problema observado es la desconexión entre disponibilidad registrada y existencia real, con urgencias de abastecimiento que pueden impedir completar un pedido. El armado de pedidos no fue identificado como el principal cuello de botella.

| Riesgo observado | Acción del software | Evidencia para evaluar valor |
|---|---|---|
| Saldo digital que no coincide con bodega | Conteo ciego por etiqueta, ubicación y responsable | Diferencias verificadas y causas documentadas |
| Mucho movimiento y poca verificación | Frecuencia ABC y ranking de rotación | Cumplimiento de conteo por clase y reincidencias |
| Una línea faltante retrasa un pedido | Compromisos próximos priorizados en móvil | Pedidos verificados antes del compromiso y faltantes detectados |
| Solicitar a Santiago cuando ya se agotó | ROP explicado, pronóstico y alerta de verificación | Urgencias, quiebres confirmados y plazo de recepción |
| Entrega parcial registrada como completa | Recepción por evento y cantidad apta | Pendientes, daños y diferencias de recepción |
| Nota de crédito interpretada como reingreso | Clasificación comercial/física y conciliación | Devoluciones vinculadas a entradas ERP sin duplicación |
| Personal con dificultad para usar un sistema amplio | Guía por etapas y acceso de bodega limitado | Tiempo para completar un conteo y errores de uso |

Estos son mecanismos para generar valor, no ahorros ya demostrados. La propuesta comercial debe incluir un piloto con línea base, responsables y criterios de aceptación. Medir antes y después exactitud en la muestra contada, urgencias a Santiago, pedidos retrasados por stock, cumplimiento del conteo y tiempo para cerrar una diferencia. No prometer porcentajes de ahorro sin evidencia.

La integración de lectura conserva Softland como fuente del registro ERP. Ajustes y documentos tributarios se gestionan por mecanismos autorizados del proveedor. La activación real depende de versión, acceso, licencia y mapeo; no se afirma compatibilidad universal.
